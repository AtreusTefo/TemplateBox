# TemplateBox

templatebox.win is a highly responsive, 100% database-free, serverless interactive web application. The platform allows everyday users to personalize text-based and visual assets — a CV/Resume builder, a Custom Canvas/Poster creator, and a print-on-demand Mockup generator — natively inside their web browser. A serverless blog runs alongside the tools for content marketing and SEO.

## Features

- Interactive CV/Resume builder with live preview, accent color theming, and ATS-compliant selectable vector text PDF export via the jsPDF native text API
- Poster and canvas creator with photo upload, caption typography, frame styles, and high-resolution PNG export via the HTML5 Canvas API
- Print-on-demand mockup generator: t-shirt, hoodie, mug, and packaging product templates with color swatches, design upload, drag-to-reposition, and PNG export
- Real-time state persistence through browser localStorage
- Strict client-side security guardrails: input sanitization before storage, textContent-only DOM writes, and image mime-type validation
- Monetized loading flow: catalog to intermediary countdown page to editor, with live Adsterra Popunder, Banner, and Social Bar placements, plus a dependency-free inline fallback that guarantees the countdown and redirect always complete even if the main script fails to load
- Serverless blog with a private, localStorage-backed admin authoring panel that exports a static post database file for deployment

## Stack

Vanilla JAMstack: HTML5, CSS3, and ES6+ JavaScript. No build step, no framework, no server-side code.

## Project Structure

`site/` is the deployable site and the Netlify publish directory, which makes it the web root: `site/index.html` is served at `/index.html`. Everything outside `site/` is documentation and configuration that is never uploaded.

```
netlify.toml            Publish directory, redirects, security headers (read at deploy time, not served)
serve.json              Local static-server config: points serve at site/, no clean URLs, / rewrite
.vscode/settings.json   Roots VS Code Live Server at /site
CLAUDE.md               Master AI instructions (AGENTS.md and GEMINI.md are identical copies)
PRD.md                  Requirements and specification
docs/                   Project documentation (see docs/DOCUMENTATION_INDEX.md)

site/                   THE PUBLISH DIRECTORY -- everything below is public
  index.html            Homepage (template catalog, category filter, guides strip)
  loading.html          10-second ad intermediary page (timer, banners, Social Bar, inline fallback)
  404.html              Not-found page, served by Netlify for every unmatched path
  resume.html           CV/Resume builder editor
  docs.html             Business document builder (receipts, invoices, warning notices)
  poster.html           Poster and canvas creator editor
  mockup.html           Print-on-demand mockup generator editor
  *-template.html       Nine search-intent landing pages, one document type each
  blog.html             Public blog index (JS-rendered cards plus a static guides archive)
  post.html             Runtime post renderer, kept as a 301 source and the admin draft preview
  admin.html            Private blog authoring panel (noindex)
  about.html            About and operator information
  terms.html            Terms of use
  privacy.html          Privacy policy and data processing notice
  blog/<slug>.html      One static page per post, generated by the admin panel
  css/style.css         Unified global stylesheet
  js/app.js             Shared logic (sanitization, filtering, countdown, editor routing)
  js/resume.js          CV builder core logic (localStorage, jsPDF)
  js/docs.js            Business document core logic (six documents, jsPDF primitives)
  js/poster.js          Poster creator core logic (HTML5 Canvas)
  js/mockup.js          Mockup generator core logic (HTML5 Canvas)
  js/blog.js            Shared blog library (content model, XSS-safe rendering, ad zone registry)
  js/blog-data.js       Static blog post database, generated by admin.html, deployed as an asset
  js/admin.js           Admin panel logic and the post-page/footer/archive generators
  assets/               Brand logo and generated Open Graph cards
  tools/og-image.html   Internal Open Graph card generator (noindex)
  robots.txt
  sitemap.xml
```

`serve.json` and `.vscode/settings.json` sit at the repository root, not in `site/`: they are local-tooling config and must never be published.

## Local Development

Run from the repository root:

```
npx serve
```

`serve.json` at the root does three things, all of them necessary: `public: "site"` points the server at the publish directory so local URLs match production (`/index.html`, not `/site/index.html`); `cleanUrls: false` stops the clean-URL redirect that strips query strings and breaks `loading.html?target=...`; and a `rewrites` entry restores `/` to `index.html`, which `cleanUrls: false` would otherwise disable — that combination is what caused a file listing to appear instead of the homepage. See `docs/error-fixes/LOCAL_INDEX_PAGE_BLANK_DIRECTORY_LISTING_INSTEAD_OF_HOMEPAGE.md`.

Run it from the repository root, not from inside `site/`, or the config is not read. The VS Code Live Server extension is configured by `.vscode/settings.json` to serve `/site` as its root. No dependencies to install.

## Deployment

Static assets, no build step. On Netlify: import the repository, leave the build command empty, and set the publish directory to `site` (`netlify.toml` already declares it). Drag-and-drop deploys use the `site` folder rather than the repository folder.
