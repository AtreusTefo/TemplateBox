# TemplateBox Documentation Index

Start here: `docs/memory/PROJECT_STATUS.md` for current build/deploy state and operational knowledge — paste it into a new chat session for full context with no re-discovery needed. Requirements live in `PRD.md` at the repo root.

**Path convention:** since July 27, 2026 the deployable site lives in `site/`, which is the Netlify publish directory and therefore the web root. Documents written before that date use unprefixed paths — read `js/app.js` as `site/js/app.js`, `index.html` as `site/index.html`. Public URLs are unaffected: `/index.html` is still `/index.html`. See `docs/architecture/ARCHITECURE.md`.

- `EXPORTED_POST_PAGE_FOOTER_DRIFT.md` — generated blog post pages shipped the pre-July-25 footer (no landing-page columns, no social row) because the footer string in `js/admin.js` was never updated with the hand-maintained pages; fixed by extracting a single `FOOTER` constant
- `HOMEPAGE_GUIDE_CARD_MISSING_EXCERPT.md` — the homepage guides strip read `post.standfirst`, a field no post has, so every card silently dropped its excerpt; fixed by reading `post.description`
- `BLOG_POSTS_NOT_CRAWLABLE_WITHOUT_JAVASCRIPT.md` — every link to a post was created in JavaScript, leaving `sitemap.xml` as the only static route to `blog/<slug>.html`; fixed with a static guides archive on `blog.html`, generated by a new admin export
- `STATIC_POST_PAGES_SERVED_NO_ADS.md` — the generated article pages carried no ad hosts and did not load `js/blog.js`, so four live Adsterra zones were inert on every page readers reach; fixed by emitting the hosts in the generator and filling them from the same `AD_ZONES` registry, plus a shared in-content placement rule
- `AD_HOST_SHIPPED_WITHOUT_ITS_SCRIPT.md` — four pages carried the site-wide anchor host with no `js/ads.js` tag, because the rollout script's guard regex matched the filename inside the comment it had just inserted; the verification shared the same substring blind spot and passed. Also fixes `privacy.html` loading no JavaScript at all, which let its four `data-target` footer links skip the loading interstitial
- `LOCAL_INDEX_PAGE_BLANK_DIRECTORY_LISTING_INSTEAD_OF_HOMEPAGE.md` — `cleanUrls: false` also disables `serve`'s directory-index resolution, so the local root URL rendered a file listing rather than the homepage; fixed by consolidating into one root `serve.json` with `public`, a `/` rewrite and no directory listing
- `PHOTO_MOCKUP_OVERLAY_WASHES_OUT_DESIGN.md` — uploaded artwork rendered pale and milky inside a photographic mockup frame because the overlay is a near-white luminance map (alpha 193, mean luma 211) drawn at the canvas default `source-over`, which paints over the design instead of shading it; fixed with a per-template `multiply` blend, whitelisted in code because Canvas silently ignores an unrecognized composite operation. Includes how to pick the blend from an asset's appearance and a pixel-level test
- `R2_CUSTOM_DOMAIN_ON_APEX_TAKES_DOWN_SITE.md` — the July 30 total outage: an R2 bucket had `templatebox.win` bound as its Custom Domain, which takes over the whole hostname, so nothing reached Netlify and an empty bucket 404'd every path. Records the destructive second step (removing the binding deletes the apex DNS record, turning a 404 into NXDOMAIN), the DNS-only-then-proxy sequencing Netlify verification requires, the `Server: cloudflare` plus `x-nf-request-id` header pair that is the only real proof, stale negative DNS caching outlasting the fix, and the two dashboard suggestions to refuse
- `CATEGORY_TABS_HIDDEN_BEHIND_HEADER_ON_PHONES.md` — `.feed-tabs` sticks at a literal 76px while `.site-header` renders 145px at 360-480px and 201px at 320px, so the entire 45px tab row sat inside the header's box and was painted over by it: category filtering was invisible and untappable on every phone width whenever the header was showing and the page was scrolled. Records why the August 14 verification missed it (it measured the header-hidden state, where the offset and the hide transform cancel exactly, not the header-revealed-while-scrolled state), the measured header heights per width, and the fix: a `--header-h` custom property published from a `ResizeObserver` on the header, with the old literals kept as `var()` fallbacks so a JavaScript failure degrades to the previous behaviour
- `IOS_SAFARI_AUTOZOOM_ON_EDITOR_FIELDS.md` — 27 text-entry fields across the four editors computed below 16px, so iOS Safari zoomed the viewport in on focus and never zoomed back out: `.doc-name` at 15px on all four, the poster text/Advanced/Download toolbars at 13px, the mockup colour and scale inputs at 12-13px. Records why the viewport meta tag was not at fault, why `maximum-scale=1` is the wrong fix (WCAG 1.4.4), the phone-scoped 16px rule, and the 168-combination overflow sweep proving the widened controls introduced no horizontal overflow
- `POPUNDER_HIJACKS_ALL_PAGE_CLICKS_FIX.md` — the Pop-Under's document-level handler observes every homepage click, so popup-blocked visitors were redirected off-site from pills, nav links and even launch buttons; fixed with an inline window-capture click shield on index.html (only `[data-target]` clicks reach the ad script), delegated pill/discard handlers, and a re-issuing launch navigation watchdog; revised July 28 with a transparent-overlay neutralizer after the shield alone left the page inert against the real ad script, whose full-viewport click-capture layer is removed only from inside the document-level listener the shield starves

## Maintenance notes not covered by a dedicated document
- Publishing a blog post is a four-artifact operation: export `js/blog-data.js` from `admin.html`, export the post pages into `site/blog/`, paste Copy Guides Archive over the `<ul>` in `site/blog.html`, and add the new URL to `site/sitemap.xml`. See `docs/implementation/BLOG_SYSTEM_IMPLEMENTATION.md`, `BLOG_POSTS_NOT_CRAWLABLE_WITHOUT_JAVASCRIPT.md`, and the July 26 entry in `PROJECT_STATUS.md`.
- The catalog CTAs must stay as anchors, not buttons. Converting them back removes the only crawlable internal links to the editor pages. See `SEO_AUDIT.md` finding 2.1.
- Adding a photographic mockup template is a data-only change: assets into `site/assets/mockups/` (URL-safe names), corners from `site/tools/mockup-admin.html`, one entry in `site/js/mockup-templates.js`, one card in `site/index.html`, one generated thumbnail, and the hero template count. No engine edits. See `docs/implementation/PHOTO_MOCKUP_TEMPLATES_IMPLEMENTATION.md`.
- The site footer is hand-maintained across every public content page plus one generator (`FOOTER` in `site/js/admin.js` for the exported blog posts). It is deliberately absent from `admin.html` (private tool), the four editors, and `loading.html` (transient/workspace pages where it added scroll length without a navigation purpose). A footer change means editing every page that still carries it and re-exporting `site/blog/`. Apply it from one script rather than by hand — see `EXPORTED_POST_PAGE_FOOTER_DRIFT.md`.
- `index.html` carried no banner at all until August 6, 2026; it now carries the same rail the editors do (and only that, plus the phone anchor) — active formats there remain banned outright. Editors carry passive banners only, selected by viewport band, up to three stacked 300x250 units on very wide screens; no active format, and Native Banner is prohibited there because it would run third-party code in the same document as the visitor's typed content. The rail is one column fixed to the window's right edge, with the page inset by one body padding that is only applied once a banner has actually filled. See `EDITOR_PAGE_AD_PLACEMENT.md` and `FIXED_FULL_HEIGHT_AD_RAIL.md`.
- Every ad placement on the site lives in `AD_ZONES` in `site/js/ads.js` — never copy the table into a second file. Pages with hosts in static markup opt into auto-mounting with `data-ads-static` on `<main>`; pages that render their own placements must not carry it, or impressions double-count. Indexable content pages carry passive banners only: no Popunder, no Social Bar. Article pages carry passive banners only: no Popunder, no Social Bar on indexable content. After changing `buildPostPage()`, re-export the post pages or the deployed ones keep the old shell. See `STATIC_POST_PAGES_SERVED_NO_ADS.md`.
- Only deployables belong in `site/`. It is the publish directory and is served verbatim, so a note or spec placed there becomes a public URL; anything outside it is never uploaded. See `INTERNAL_FILES_PUBLICLY_SERVED.md`.
- Run `node tests/verify-layout.js` before deploying. Nothing runs it automatically. It covers ad wiring, selector hooks, the fixed rail's inset contracts across five pages and ten widths, the launch flow, and an ads-blocked comparison against the last commit. See `RUNNING_THE_VERIFICATION_SUITE.md`. **Two test files this project's notes once described, `test-home.js` and `verify-site.js`, never existed** - if a guarantee is written down as tested, check that a check exists.
- Local testing is `npx serve` from the repository root, where `serve.json` points the server at `site/`. Not from inside `site/`, and never with `cleanUrls: false` alone — see `LOCAL_INDEX_PAGE_BLANK_DIRECTORY_LISTING_INSTEAD_OF_HOMEPAGE.md`.
- Click handlers on index.html must be window-capture delegated, not element-level: the ad click shield in the page head stops non-launch clicks from propagating below `window`, so an element-level listener there never fires. Launch controls (`[data-target]`) are the one exemption. New external links on index.html need their host added to the shield's allowlist. See `POPUNDER_HIJACKS_ALL_PAGE_CLICKS_FIX.md`.
