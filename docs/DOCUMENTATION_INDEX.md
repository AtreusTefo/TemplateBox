# TemplateBox Documentation Index

Start here: `docs/memory/PROJECT_STATUS.md` for current build/deploy state and operational knowledge — paste it into a new chat session for full context with no re-discovery needed. Requirements live in `PRD.md` at the repo root.

**Path convention:** since July 27, 2026 the deployable site lives in `site/`, which is the Netlify publish directory and therefore the web root. Documents written before that date use unprefixed paths — read `js/app.js` as `site/js/app.js`, `index.html` as `site/index.html`. Public URLs are unaffected: `/index.html` is still `/index.html`. See `docs/architecture/ARCHITECURE.md`.

- `LOCAL_SERVE_CLEAN_URL_DROPS_TARGET_QUERY.md` — `npx serve .`'s default clean-URL redirect drops the loading page's `?target=` query, sending every editor launch to the fallback default during local testing only; fixed via `serve.json`
- `INTERNAL_FILES_PUBLICLY_SERVED.md` — `publish = "."` served the entire `docs/` tree and every instruction/spec file over HTTP, including the ad zone keys and analytics IDs in `PROJECT_STATUS.md`; fixed with 404 redirect rules, with the rejected `site/` publish-directory alternative recorded
- `EXPORTED_POST_PAGE_FOOTER_DRIFT.md` — generated blog post pages shipped the pre-July-25 footer (no landing-page columns, no social row) because the footer string in `js/admin.js` was never updated with the hand-maintained pages; fixed by extracting a single `FOOTER` constant
- `HOMEPAGE_GUIDE_CARD_MISSING_EXCERPT.md` — the homepage guides strip read `post.standfirst`, a field no post has, so every card silently dropped its excerpt; fixed by reading `post.description`
- `BLOG_POSTS_NOT_CRAWLABLE_WITHOUT_JAVASCRIPT.md` — every link to a post was created in JavaScript, leaving `sitemap.xml` as the only static route to `blog/<slug>.html`; fixed with a static guides archive on `blog.html`, generated by a new admin export
- `STATIC_POST_PAGES_SERVED_NO_ADS.md` — the generated article pages carried no ad hosts and did not load `js/blog.js`, so four live Adsterra zones were inert on every page readers reach; fixed by emitting the hosts in the generator and filling them from the same `AD_ZONES` registry, plus a shared in-content placement rule
- `LOCAL_INDEX_PAGE_BLANK_DIRECTORY_LISTING_INSTEAD_OF_HOMEPAGE.md` — `cleanUrls: false` also disables `serve`'s directory-index resolution, so the local root URL rendered a file listing rather than the homepage; fixed by consolidating into one root `serve.json` with `public`, a `/` rewrite and no directory listing
- `POPUNDER_HIJACKS_ALL_PAGE_CLICKS_FIX.md` — the Pop-Under's document-level handler observes every homepage click, so popup-blocked visitors were redirected off-site from pills, nav links and even launch buttons; fixed with an inline window-capture click shield on index.html (only `[data-target]` clicks reach the ad script), delegated pill/discard handlers, and a re-issuing launch navigation watchdog

## Maintenance notes not covered by a dedicated document
- Publishing a blog post is a four-artifact operation: export `js/blog-data.js` from `admin.html`, export the post pages into `site/blog/`, paste Copy Guides Archive over the `<ul>` in `site/blog.html`, and add the new URL to `site/sitemap.xml`. See `docs/implementation/BLOG_SYSTEM_IMPLEMENTATION.md`, `BLOG_POSTS_NOT_CRAWLABLE_WITHOUT_JAVASCRIPT.md`, and the July 26 entry in `PROJECT_STATUS.md`.
- The catalog CTAs must stay as anchors, not buttons. Converting them back removes the only crawlable internal links to the editor pages. See `SEO_AUDIT.md` finding 2.1.
- The site footer exists in 22 hand-maintained copies plus one generator. A footer change means editing every page under `site/` except `admin.html`, the `FOOTER` constant in `site/js/admin.js`, and re-exporting the pages in `site/blog/`. Apply it from one script rather than by hand — see `EXPORTED_POST_PAGE_FOOTER_DRIFT.md`.
- Every ad placement on the site lives in `AD_ZONES` in `site/js/ads.js` — never copy the table into a second file. Pages with hosts in static markup opt into auto-mounting with `data-ads-static` on `<main>`; pages that render their own placements must not carry it, or impressions double-count. Indexable content pages carry passive banners only: no Popunder, no Social Bar. Article pages carry passive banners only: no Popunder, no Social Bar on indexable content. After changing `buildPostPage()`, re-export the post pages or the deployed ones keep the old shell. See `STATIC_POST_PAGES_SERVED_NO_ADS.md`.
- Only deployables belong in `site/`. It is the publish directory and is served verbatim, so a note or spec placed there becomes a public URL; anything outside it is never uploaded. See `INTERNAL_FILES_PUBLICLY_SERVED.md`.
- Local testing is `npx serve` from the repository root, where `serve.json` points the server at `site/`. Not from inside `site/`, and never with `cleanUrls: false` alone — see `LOCAL_INDEX_PAGE_BLANK_DIRECTORY_LISTING_INSTEAD_OF_HOMEPAGE.md`.
- Click handlers on index.html must be window-capture delegated, not element-level: the ad click shield in the page head stops non-launch clicks from propagating below `window`, so an element-level listener there never fires. Launch controls (`[data-target]`) are the one exemption. New external links on index.html need their host added to the shield's allowlist. See `POPUNDER_HIJACKS_ALL_PAGE_CLICKS_FIX.md`.
