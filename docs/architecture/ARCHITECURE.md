# Folder Structure

Updated: July 27, 2026 (deployable files moved into `site/`)

The repository has two top levels with one rule between them: `site/` is the Netlify publish directory and therefore the web root, and everything outside it is never uploaded. `site/index.html` is served at `/index.html`; a file placed anywhere in `site/` is a public URL, and a file placed outside it cannot be fetched at all.

## Consequences of this layout worth knowing

- **Local testing runs `npx serve` from the repository root**, where `serve.json` points the server at `site/`. Serving the root without that config puts every page one directory below the web root and breaks relative asset paths, and running the command from inside `site/` misses the config entirely.
- **Drag-and-drop deploys use the `site` folder**, not the repository folder.
- **Nothing needs a redirect rule to stay private.** Documentation and local tooling sit outside the publish directory, which is a structural guarantee rather than a list to maintain. There are no exceptions left: `netlify.toml` carries no internal-file 404 rules at all.
- **Public URLs did not change** in the move: the publish directory becomes the web root, so `/rent-receipt-template.html` is still `/rent-receipt-template.html`. No canonical, sitemap entry or inbound link needed rewriting.

## Extension points that must stay in sync

- Adding an editor: register it in `EDITOR_ROUTES` **and** the `EDITORS` registry in `site/js/app.js`, and in the mirrored inline `ROUTES` table in `site/loading.html`. See `docs/error-fixes/LOCAL_SERVE_CLEAN_URL_DROPS_TARGET_QUERY.md` and the implementation notes in `docs/implementation/`.
- The site footer exists in 22 hand-maintained copies plus the `FOOTER` constant in `site/js/admin.js`. Changing it means all of them, then re-exporting the pages in `site/blog/`.
- Ad placements exist only in `AD_ZONES` in `site/js/ads.js`. Pages whose hosts are in static markup opt into auto-mounting with `data-ads-static` on `<main>`; pages that mount through a renderer (`blog.html`, `post.html`) must not carry it.
- Publishing a post touches four things: `site/js/blog-data.js`, `site/blog/<slug>.html`, the archive list in `site/blog.html`, and `site/sitemap.xml`.
